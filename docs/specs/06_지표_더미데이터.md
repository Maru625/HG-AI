# 06. 지표와 더미 데이터

> 기준: 설계서 8.2. 생성기: `seedgen/` (seed 20261112). 생성 가정과 결과는 `seed/generation_log.md`에 자동으로 남는다.
> 모든 값은 더미다. 특정 수치(예: 하루 1시간)에 맞추려고 값을 고치지 않았다.

## 1. 과제 지정 데이터 → 파일

| 과제 데이터 | 파일 | 내용 |
|---|---|---|
| 직급별 업무 시간 할당량 | `seed/dashboard/work_allocation.csv`, 엑셀 시트 `직급별_업무시간_할당량` | 직급군 5개 × (본업·회의·전결 단계 6개·기타 사무) × 주당 시간 |
| 가장 하기 싫은 업무 설문 | `seed/dashboard/survey.csv`, 엑셀 시트 `설문_문항`·`설문_응답`·`설문_집계` | 120명, 1~3순위(전결 단계 6개 + 기타 사무), 자가 응답 주당 시간, 이유 |
| (함께 쓰는 데이터) 부서별 야근 기록 | `seed/dashboard/overtime.csv` | 8주, 날짜·직원·부서·시간·원인(상위 범주, 전결 처리면 단계까지) |
| (함께 쓰는 데이터) 과거 결재 이력 | `seed/history.json` | 162건, 반려 사유 범주, 결재자별 처리 시각 |
| 자동화 효과 가정표 | `seed/dashboard/automation_assumptions.csv` | 전결 단계별 가정 절감률과 그 기능 |

- 엑셀 `seed/과제_활용데이터.xlsx`: 설명 시트 + 4개 시트. 합계·순위·집계는 수식(SUM, IF, COUNTIF, COUNTIFS, RANK, AVERAGEIF)이고 입력값은 파란 글자. 저장소에는 값까지 계산해 둔 판을 넣었다. `approval-seed build`로 다시 만들면 수식만 들어가고, 엑셀이 열 때 다시 계산한다.

## 2. 홈 대시보드 지표 (`core/dashboard.py`)

| 지표 | 계산 | 지금 시드 값 |
|---|---|---|
| 야근 시간 중 전결 처리 비중 | 전결 처리 원인 야근 시간 ÷ 전체 야근 시간 (8주) | 29% (150 / 526시간). 부서별: 연구1팀 33%, 연구2팀 18%, 시험평가팀 32%, 경영지원팀 34% |
| 반려율 | 반려 ÷ 완료(승인+반려) 과거 이력 | 17% (27 / 162) |
| 결재 대기 | 지금 결재할 차례인 문서 수 | 시드 3건 (시연 중 늘어남) |
| 예상 절감 (가정) | 1인 하루 = Σ(전결 단계별 주당 시간 × 가정 절감률) ÷ 5, 직급군 평균 | 약 41분 |
| 부서별 야근 원인 | 부서 × 상위 범주 시간 | 그래프 + 표 |
| 직급별 전결 단계 시간 | 할당량의 전결 단계 6개 주당 시간 | 표(진하기) |
| 가장 하기 싫은 업무 | 1순위 3점, 2순위 2점, 3순위 1점 합 | 증빙 준비 159 · 문서 작성 137 · 반려 후 재작성 136 … |
| 반려 사유 | 과거 이력 반려 사유 범주별 건수 | 필수 항목 누락 8 · 증빙 누락 7 · 한도 초과 사유 부족 7 … |
| 결재자별 대기 | 지금 대기 수, 과거 평균 처리 시간(업무 시간) | 박서연 팀장 3건 · 평균 6.3시간 |

- 반려 사유 범주는 검증 규칙(02 문서 2장)과 맞췄다. 그래서 "이 반려는 상신 전 검증으로 막을 수 있었다"로 바로 이어진다.
- 절감은 목표치와 비교하지 않고 단계별 추정치만 보여준다(설계서 13.2).

## 3. 결정성

- 같은 seed면 json·csv·영수증 이미지가 바이트 단위로 같다(엑셀 제외: 파일 안에 만든 시각이 들어감). `tests/test_determinism.py`가 확인한다.
- `approval-server reset`을 두 번 해도 DB 내용이 같다(실제 시각 칸 제외).
- 생성기 검사 14개: `uv run approval-seed check`.
