## 2. 상태와 전이

```
작업 계획   PENDING ─approve_plan(①)→ APPROVED
            PENDING/APPROVED ─cancel_plan→ CANCELED (상신 전 문서도 함께 CANCELED)

문서        (save) → INVALID ⇄ VALID ─confirm(②, 원본 대조 표시 포함)→ CONFIRMED ─submit(③)→ SUBMITTED ─마지막 승인→ APPROVED
                                     CONFIRMED ─다시 save→ VALID (확인·원본 대조 해제, version+1)
                                                         SUBMITTED ─반려(합의 거부 포함)→ REJECTED ─같은 항목 save 또는 화면 [고쳐서 다시 기안]→ 새 문서(original_doc_id)
            INVALID/VALID/CONFIRMED ─계획 취소 또는 화면 [초안 취소]→ CANCELED
            (화면 새 기안) → INVALID/VALID … CONFIRMED ─화면 [상신](③)→ SUBMITTED

결재 단계   WAITING → PENDING(차례) → APPROVED / REJECTED,  반려 시 남은 WAITING → SKIPPED
회의실 예약 (MTG-01 상신) HOLD → 최종 승인 CONFIRMED / 반려 RELEASED
```

- 회의실 가위바위보(재미 기능): 도전자가 이기면 수비자 예약 RELEASED(결재대기 신청이었으면 그 문서 CANCELED, 결재 단계 SKIPPED, 기안자에게 결과 알림), 겹침이 더 없으면 도전자 초안에 HOLD를 잡고 초안을 다시 검증한다. 초안의 날짜·시간·회의실을 바꾸거나 초안·계획을 취소하면 그 HOLD는 RELEASED.
- 예전 DB 파일로 새 코드를 켜면 서버가 없는 표·열을 더한다(`db.ensure_schema`). 열을 지우거나 형식을 바꾸지는 않는다.
- [보완] 문서 상태 `CANCELED`를 더했다. 설계서 5.2에는 계획 취소 시 문서가 어떻게 되는지 상태값이 없었다.
- 확인 뒤 고친 문서를 상신하면 `MODIFIED_AFTER_CONFIRM`(확인했던 판과 지금 판을 함께 알려 줌), 한 번도 확인하지 않았으면 `NOT_CONFIRMED`.
- 화면 [상신]은 화면에서 쓴 문서(created_via=WEB)에만 있다. AI가 쓴 문서의 상신은 대화에서 `submit_drafts`로 한다(설계서 4장의 확인 ③).

> **10/23 규정 확장 [변경]** 이전 문서 전이에는 원본 대조, 화면 새 기안·상신·초안 취소·다시 기안이 없었다. 문서에 original_checked(_at), 결재 단계에 delay_reason·delay_until·delay_at, 알림 종류에 RESULT·DELAY를 더했다.

## 3. 시연 시계 (설계서 5.4)

- `demo_state.clock = {demo_start, real_start}` → `지금 = demo_start + (실제 지금 − real_start)`.
- 시연 제어 패널의 '시각 맞추기'는 두 값을 다시 잡고, '+N분'은 demo_start만 옮긴 뒤 알림 주기 작업을 바로 한 번 돈다.
- 영업일은 주말과 `seed/calendar.json`의 공휴일을 뺀다.

## 4. 오류 응답

`{ok: false, code, message, fix_hint, details}` — 코드 목록은 `core/errors.py`, 툴별 설명은 04 문서.
설계서 6.4의 11개에 일반 코드 5개(`ALREADY_SUBMITTED`, `NOT_FOUND`, `FORBIDDEN`, `BAD_REQUEST`, `UNAUTHORIZED`)와 `ORIGINAL_CHECK_REQUIRED`(10/23, 제22조)를 더했다.
