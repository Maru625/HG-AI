# 02. 전결 규정 (더미)

> 원본: `seedgen/source/regulations.yaml` → 생성: `seed/regulations.md`(조항 전문), `seed/processes.json`(프로세스 정의).
> 규정을 바꾸려면 원본을 고치고 `uv run approval-seed build`를 다시 돌린다. 웹 화면 '규정'에서 같은 내용을 본다.

## 1. 프로세스 5종

| ID | 이름 | 전결 기준 | 합의 | 한도 | 기한 | 증빙 | 근거 |
|---|---|---|---|---|---|---|---|
| EXP-01 | 일반경비 정산 | 30만 이하 팀장 / 100만 이하 실장 / 초과 본부장 | — | 회의비 1인 5만 원 | 사용 후 정산 | 영수증 | 제10조, 제10조의2 |
| EXP-02 | 국내 출장비 정산 | 50만 이하 팀장 / 초과 실장 | — | 숙박 1박: 사원·선임 10만, 책임·수석 12만 / 식비 1일 3만 | 출장 종료 후 정산 | 영수증(교통비·숙박비·식비) | 제11조, 제11조의2 |
| RPT-01 | 출장결과보고 | 팀장 | — | — | 출장 종료 후, 종료일 후 5영업일 안 | 회의 자료(선택) | 제12조 |
| PUR-01 | 물품 구매 요청 | 50만 이하 팀장 / 300만 이하 실장 / 초과 본부장 | 300만 초과 시 경영지원팀 | — | 구매 전(희망 납기가 지나지 않음) | 견적서 | 제13조 |
| MTG-01 | 회의실 사용 신청 | 팀장 | 대회의실·외부인 참석·업무시간 외(주말·공휴일 포함) 사용 시 경영지원팀 | 정원 | 사용 전 신청 | 없음 | 제14조 |

- 결재선 원칙(제3조): 기안자 → 팀장 → 실장 → 본부장 순, 전결권자까지만. 기안자가 팀장이면 팀장 단계 생략. **기안자가 전결권자 본인이라 결재할 사람이 없으면 바로 위 직책자**(팀장 기안 → 실장, 실장 기안 → 본부장). 합의 부서장은 결재선 끝(이미 결재선에 있는 사람이면 생략).
- 처리 기한(제4조): 결재 차례가 온 날부터 3영업일. 처리할 수 없으면 결재자가 화면에서 기안자에게 사유를 알린다.
- 증빙 공통(제20~22조): 첨부 필수, 같은 영수증 중복 정산 금지, 주말·공휴일 사용은 사유, 판독이 불확실하면 확인 ② 때 원본 대조 표시.
- 조항별 대응과 해 볼 수 있는 사례는 08 문서(규정 대응표).

> **10/23 규정 확장 [변경]**
> - 이전 표의 '기한' 칸은 RPT-01만 "출장 종료일 후 5영업일", 나머지는 "—"였다. 시점 규칙(사용 후·종료 후·구매 전·사용 전)을 서버가 판정하게 되어 칸을 채웠다.
> - 이전 결재선 원칙: "기안자 → 팀장 → 실장 → 본부장 순, 전결권자까지만. 기안자가 팀장이면 팀장 단계 생략. 합의 부서장은 결재선 끝." 위 본문은 제3조 원문에 더한 문장(위 직책자 결재)을 반영했다.
> - 이전 증빙 공통: "같은 영수증 중복 정산 금지, 주말·공휴일 사용은 사유, 판독이 불확실하면 원본 확인."

## 2. 검증 규칙 (설계서 7.4, `core/validation.py`)

| 코드 | 수준 | 판정 | 사람이 할 일 |
|---|---|---|---|
| REQUIRED_MISSING | 오류 | 필수 항목·목록 하위 항목(후속 조치의 담당·기한 등)이 비어 있음 | AI가 사용자에게 묻는다 |
| INVALID_VALUE | 오류 | 날짜·시각·숫자 형식, 시작>종료, 없는 회의실 등 | — |
| EVIDENCE_REQUIRED | 오류 | 증빙 필수인데 없음 | — |
| ATTACHMENT_MISSING | 오류 | 필수 증빙에 첨부 파일 이름이 없음 (제20조, 견적서는 제13조) | 첨부한다 |
| TIMING | 오류 | 규정이 정한 시점과 날짜가 맞지 않음: 사용 전 정산(제10조), 출장 종료 전 정산·보고(제11·12조), 희망 납기 경과(제13조), 지난 시각 회의실(제14조), 오늘보다 뒤 날짜의 증빙 | 날짜를 확인한다 |
| SUM_MISMATCH | 오류 | 합계·금액이 증빙 합 또는 수량×단가와 다름 | — |
| DUPLICATE_EVIDENCE | 오류 | (날짜, 상호, 금액)이 **같은 기안자**의 상신·승인 문서 또는 같은 문서 안에 있음 | 증빙을 뺀다 |
| LIMIT_EXCEEDED | 사유 없으면 오류 / 있으면 경고 | 숙박 1박·식비 1일·회의비 1인 한도 초과 | 사유(reason_key) 입력 |
| HOLIDAY_USE | 경고, 사유 없으면 확인 불가 | 주말·공휴일 사용 | 사유 입력 |
| DEADLINE_PASSED | 경고 | 처리 기한 경과 | — |
| LOW_CONFIDENCE | 경고 | 판독 신뢰도 0.8 미만 | 확인 ② 때 원본과 대조했다고 표시 (없으면 확인 단계에서 ORIGINAL_CHECK_REQUIRED) |
| ROOM_CAPACITY | 오류 | 인원 > 정원 | — |
| ROOM_CONFLICT | 오류 | 같은 회의실·시간대에 확정 또는 가예약 | 다른 회의실·시간 |

- [보완] 중복 판정을 "같은 기안자 기준"으로 정했다. 고속철도 요금처럼 다른 사람과 날짜·상호·금액이 같을 수 있어서다(설계서 v1.0에는 기준이 없었다).
- 사유는 `reasons`에 `reason_key → 사유 문장`으로 넣는다. 키 예: `LIMIT_EXCEEDED:3`(증빙 3번), `LIMIT_EXCEEDED:meal:2026-11-05`, `LIMIT_EXCEEDED:per_person`(회의비 1인당), `HOLIDAY_USE:1`. 화면에서는 "증빙 3 한도 초과 사유"처럼 읽기 쉽게 보인다.
- 확인 ② 단계 규칙(`core/services.py`): 오류가 있으면 VALIDATION_FAILED, 사유가 비면 REASON_REQUIRED, 판독 신뢰도가 낮은 증빙을 원본과 대조했다는 표시가 없으면 ORIGINAL_CHECK_REQUIRED. 문서를 고치면 확인과 원본 대조 표시가 함께 풀린다.

> **10/23 규정 확장 [추가]** ATTACHMENT_MISSING, TIMING, ORIGINAL_CHECK_REQUIRED를 더했다. 이전 LOW_CONFIDENCE의 '사람이 할 일'은 "원본 확인"이었고 서버가 확인 여부를 기록하지 않았다.

## 3. 결재 검토 지원 규칙 (설계서 7.6, `core/review.py`)

| 중요도 | 조건 (하나라도) |
|---|---|
| 긴급 | 회의일까지 3영업일 이내 / 업무 처리 기한(결과보고 등)까지 2영업일 이내 / 지금 단계 시작 후 3영업일 넘게 대기(제4조 처리 기한 초과) |
| 보통 | 주의 항목이 하나 이상 |
| 낮음 | 그 밖 |

| 주의 항목 | 내용 |
|---|---|
| LIMIT_EXCEEDED, HOLIDAY_USE | 사유를 붙여 넘어온 경고 (기안자 사유 함께 표시) |
| LOW_CONFIDENCE | 판독 신뢰도가 낮은 증빙의 판독값 |
| DEADLINE_PASSED | 기한 경과 |
| NEAR_LIMIT | 금액이 전결 기준의 90% 이상 (분할 청구 확인) |
| SIMILAR_RECENT | 같은 기안자가 7일 안에 같은 사용처를 다른 날짜로 정산 |
| RESUBMIT_CHANGES | 반려 후 재상신: 바뀐 항목과 증빙 변경 여부 |

- 알림: 긴급 문서가 새로 생기면 즉시 알림(같은 문서로 두 번 보내지 않음), 영업일 09:00·14:00 정기 알림. 어느 알림이든 결재할 차례인 문서 **전체**를 중요도순으로 묶는다.
- 기안자 알림(10/23 추가): 최종 승인·반려·합의 거부 결과(RESULT), 결재자가 알린 처리 지연 사유(DELAY, 제4조).
- 처리 기한(10/23 추가, `review.step_due`): 결재 차례가 온 날(첫 단계는 상신일) + 3영업일. 결재함·결재 검토·기안자 문서 화면과 `list_pending_approvals`·`get_status` 결과에 기한과 경과가 나온다.
- LOW_CONFIDENCE 주의 항목에는 기안자의 원본 대조 여부와 시각이 함께 나온다(10/23 추가).
