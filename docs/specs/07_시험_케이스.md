# 07. 시험 케이스

> 기준: 설계서 14.3 7단계(시험 케이스 10종), 5장(상태 전이). 실행: `uv run pytest` (임시 DB를 써서 시연용 DB는 건드리지 않는다).

## 1. 설계서 시험 케이스 10종

| # | 케이스 | 시험 함수 (`tests/`) | 기대 결과 |
|---|---|---|---|
| TC01 | 정상 | `test_cases.py::test_tc01_normal_flow` | 대본대로 3건 상신 → 팀장 전결 1단계 → 모두 승인, 회의실 확정, 감사 기록에 MCP·WEB 구분 |
| TC02 | 순서 위반 | `test_tc02_order_violations` | 승인 전 저장 PLAN_NOT_APPROVED, 확인 전 상신 NOT_CONFIRMED, 오류 문서 확인 VALIDATION_FAILED, 취소 계획 PLAN_CANCELED, 남의 계획 FORBIDDEN |
| TC03 | 중복 | `test_tc03_duplicate_evidence` | 5번 영수증 제외 제안(기존 문서번호 포함), 넣고 저장하면 INVALID, 다른 기안자에게는 중복 아님 |
| TC04 | 한도 초과 | `test_tc04_limit_exceeded`, `test_tc04b_holiday_use_reason_required` | 사유 없으면 오류, 사유 넣으면 경고로 통과하고 결재자 주의 항목에 사유와 근거 조항. 휴일 사용은 사유 없으면 REASON_REQUIRED |
| TC05 | 확인 후 수정 | `test_tc05_modified_after_confirm` | 고치면 확인 해제(v2) → 상신 시 MODIFIED_AFTER_CONFIRM → 다시 확인 후 상신. 상신 문서 수정은 ALREADY_SUBMITTED |
| TC06 | 반려 후 재기안 | `test_tc06_reject_and_resubmit` | 반려 사유 조회, 같은 항목 저장 → 원문서를 잇는 새 문서, 결재자에게 RESUBMIT_CHANGES |
| TC07 | 화면 확인형 모드 | `test_tc07_confirm_in_ui_mode` | B 모드에서 MCP 승인·확인은 CONFIRM_IN_UI_REQUIRED(화면 링크), 화면에서 하면 통과 |
| TC08 | 회의실 가예약 충돌, 반려 시 해제 | `test_tc08_room_hold_conflict_and_release` | 확정 예약과 겹치면 ROOM_CONFLICT, 상신하면 가예약, 남이 같은 시간을 찾으면 겹침, 반려하면 해제되어 다시 비어 있음 |
| TC09 | 긴급 결재 묶음 알림 | `test_tc09_urgent_notification_bundles_all_pending` | 상신 즉시 알림 1건에 대기 6건 전체가 중요도순, 같은 문서로 다시 알리지 않음, 14:00 정기 알림 |
| TC10 | 결재선 밖 조회 차단 | `test_tc10_access_outside_approval_line` | 결재선 밖 결재자 NOT_IN_APPROVAL_LINE, 역할이 다른 연결 FORBIDDEN, MCP로 결재 FORBIDDEN, 차례 아닌 사람 결재 불가 |

## 2. 상태 전이 확인

| 대상 | 전이 | 지나는 시험 |
|---|---|---|
| 작업 계획 | PENDING→APPROVED, PENDING→CANCELED, APPROVED→CANCELED | TC01, `test_transitions_plan_cancel_cascades` |
| 문서 | INVALID→VALID, VALID→CONFIRMED, CONFIRMED→VALID, CONFIRMED→SUBMITTED, SUBMITTED→APPROVED, SUBMITTED→REJECTED, 상신 전→CANCELED, REJECTED→재기안 | TC01·TC04·TC05·TC06, `test_transitions_plan_cancel_cascades` |
| 결재 단계 | WAITING→PENDING→APPROVED, PENDING→REJECTED, WAITING→SKIPPED, 합의 단계 | `test_transitions_multi_step_and_agreement`, `test_large_room_needs_agreement` |
| 회의실 예약 | HOLD→CONFIRMED, HOLD→RELEASED | TC01, TC08 |

## 3. 그 밖의 시험

| 파일 | 내용 |
|---|---|
| `test_cases.py` | 반려 의견 필수, 결재 중요도 규칙(시드 대기 3건의 긴급·보통·낮음과 NEAR_LIMIT·SIMILAR_RECENT) |
| `test_web_api.py` | REST 인증·역할, 결재 엔드포인트 없음, 오류 형식, 막힌 쓰기 시도의 작업 기록, 화면 링크, 모든 화면 렌더링(두 사용자), 화면으로 대본 전체(확인 ②, 토스트 6건, 중요도순, 주의 행 강조, 반려 의견 필수, 회의실 확정, 작업 기록), 시연 제어 패널 |
| `test_mcp_e2e.py` | 실제 MCP 클라이언트로 MCP 서버(stdio)를 띄워 툴 범위(14/8개, readOnlyHint), 서버 지침, **대본 전체 재현**(기안자 대화 → 결재자 대화 → 화면 승인), 전결 서버가 꺼졌을 때 SERVER_UNAVAILABLE, stdio 표준 출력에 잡글 없음, ChatGPT용 HTTP(한 포트에 연결 2개, 비밀 경로, 다른 Host 허용, JSON 응답) |
| `test_determinism.py` | reset 두 번 같은 DB, 생성기 두 번 같은 파일, 저장소 시드와 같은지 |

## 4. 최근 실행

- 32개 통과 (Python 3.12, 약 30초).
- 손으로 확인한 것: Playwright로 화면 10종 캡처(1366px·390px), 자동 갱신(화면 밖 저장이 3초 안에 반영), 토스트 닫기, 승인·반려 확인창, streamable HTTP 연결(결재자용, 경로 비밀값).
