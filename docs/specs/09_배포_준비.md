# 09 서버 배포 준비 (10/23)

지금까지는 발표 PC 한 대에서 전결 서버(8000)와 MCP 서버(8765)를 따로 띄워 ChatGPT 데스크톱 앱에 붙였다.
이 문서는 **서버 한 대에 올려 여러 사람이 쓰게 할 때** 달라지는 점과, 그에 맞춰 코드에 넣어 둔 준비를 적는다.
외부 서비스 내용은 [사실](출처 번호)과 [해석]을 나눠 적었다. 출처는 맨 아래에 있다(10/23 확인).

> 모든 데이터는 시연용 더미다. 배포 서버에도 실제 회사 자료를 넣지 않는다.

**결정 (10/23): 배포 뒤에도 ChatGPT + MCP만 쓴다.** 참가자는 각자 ChatGPT 데스크톱 앱에 연결을 등록한다(웹의 **AI 연결** 화면).
사이트 안 챗봇은 별도 LLM API 키·사용료와 두 경로 운영이 필요해 만들지 않는다. ChatGPT 계정으로 사이트에 직접 붙는 길
(Sign in with ChatGPT)은 지금 쓸 수 없다(7장).

## 1. 배포하면 무엇이 달라지나

| 항목 | 지금 (발표 PC 로컬 시연) | 배포 후 |
|---|---|---|

| MCP 주소 | `http://127.0.0.1:8765/mcp/<비밀값>/drafter` | `https://<공개 주소>/mcp/<비밀값>/drafter` (웹과 같은 주소) |

| 연결 등록 | 발표 PC 1대에 한 번 | 참가자 각자(데스크톱 앱) — 웹의 **AI 연결**(`/connect`) 화면에서 주소 복사. ChatGPT 웹은 워크스페이스 관리자 |

| 화면 링크 | `http://localhost:8000/...` | `APPROVAL_BASE_URL`(공개 주소)로 만든다 |
| 예전 DB | — | 서버가 켜질 때 빠진 표·열을 더한다(`db.ensure_schema`). 지우지 않는다 |

## 2. 실행 방법

### 2.1 uv로 바로

```bash
export APPROVAL_BASE_URL=https://demo.example.com     # 공개 주소(HTTPS는 앞단 프록시가 붙인다)
export APPROVAL_MCP_SECRET=<임의 문자열>                # 주소 비밀값과 헤더 토큰의 바탕
export APPROVAL_ADMIN_KEY=<운영자 키>
export APPROVAL_SITE_KEY=<입장 코드>                   # 선택
export APPROVAL_CLOCK_FLOW=frozen
uv run approval-server deploy --port 8000             # 0.0.0.0:8000에서 웹+REST+MCP
```

켜지면 등록할 MCP 주소 8개와 헤더 토큰 방식 주소를 출력한다. 같은 내용이 웹의 **AI 연결(`/connect`)** 화면(참가자용, 복사 버튼)과
**시연 제어 패널(`/demo`)**에 나온다.
DB가 없으면 먼저 시드를 적재한다. 상태 확인은 `GET /healthz` → `approval-demo ok + MCP`.

### 2.2 Docker

```bash
docker build -t approval-demo .
docker run -p 8000:8000 -v approval-data:/app/data \
  -e APPROVAL_BASE_URL=https://demo.example.com -e APPROVAL_MCP_SECRET=<임의 문자열> \
  -e APPROVAL_ADMIN_KEY=<운영자 키> -e APPROVAL_SITE_KEY=<입장 코드> approval-demo
```

- 이미지에는 `core web mcp_server seedgen seed demo_inputs`만 들어간다(`.dockerignore`). DB와 비밀값은 `/app/data` 볼륨에 남는다.
- [확인 범위] 이 작업 환경에서는 Docker Hub가 막혀 이미지를 실제로 빌드하지 못했다. 대신 이미지에 들어가는 파일만 따로 모아
  `uv sync --frozen --no-dev` → `approval-server deploy`를 돌려 웹·입장 코드·MCP가 뜨는 것까지 확인했다.

### 2.3 서버 한 대에 HTTPS까지 (deploy 폴더: docker compose + Caddy)

도메인 하나와 서버(VM) 한 대가 있으면 HTTPS까지 한 번에 띄운다. Caddy가 인증서를 자동으로 받고, 앱 포트는 밖에 열지 않는다.

```bash
# 도메인 DNS(A 레코드)를 서버 IP로, 방화벽 80·443 열기
cd deploy
cp .env.example .env          # APPROVAL_DOMAIN, APPROVAL_MCP_SECRET, APPROVAL_ADMIN_KEY, APPROVAL_SITE_KEY 채우기
docker compose up -d --build  # https://<도메인>
docker compose down           # 시연이 끝나면 (데이터까지 지우려면 down -v)
```

- [확인 범위] `docker compose config`로 설정 파일(값 채우기·빠진 값 오류)만 확인했다. 이 환경에서는 이미지·Caddy를 받을 수 없어 실제로 띄우지는 못했다.
- 조마다 서버를 나누려면 조마다 이 폴더를 복사해 도메인(또는 하위 도메인)·비밀값·입장 코드를 다르게 둔다.

### 2.4 HTTPS와 프록시

앱은 TLS를 하지 않는다. 클라우드 플랫폼·로드 밸런서·리버스 프록시가 HTTPS를 붙이고 이 포트로 넘긴다.
프록시가 보내는 `X-Forwarded-*` 헤더를 믿도록 실행한다(`proxy_headers`). SSE를 못 넘기는 프록시도 있어 MCP 응답은 JSON 한 덩어리로 보낸다.

### 2.5 환경 변수

| 변수 | 기본 | 뜻 |
|---|---|---|
| `APPROVAL_BASE_URL` | `http://localhost:8000` | 공개 주소. 화면 링크, MCP 주소 안내, Host 검사에 쓴다 |
| `APPROVAL_PORT` / `APPROVAL_HOST` | 8000 / `0.0.0.0`(deploy) | 듣는 포트·주소 |
| `APPROVAL_MCP_MOUNT` | deploy·Docker에서 켜짐 | MCP를 웹과 같은 포트에 연다 |
| `APPROVAL_MCP_SECRET` | `data/mcp_secret.txt`에 만들어 씀 | 주소 비밀값. **바꾸면 주소와 헤더 토큰이 모두 바뀐다**(시연 뒤 닫을 때 쓴다) |
| `APPROVAL_INTERNAL_URL` | `http://127.0.0.1:<포트>` | MCP 툴이 REST API를 부르는 서버 안 주소 |
| `APPROVAL_PUBLIC_HOSTS` | (없음) | Host·Origin 검사에 더 허용할 호스트(쉼표). `APPROVAL_BASE_URL`의 호스트는 자동 포함 |
| `APPROVAL_SITE_KEY` | (없음) | 웹 입장 코드. 두면 코드를 넣은 브라우저만 화면을 쓴다(30일 기억). 링크 `https://<주소>/?enter=<코드>`로 바로 입장 |
| `APPROVAL_ADMIN_KEY` | (없음) | 운영자 키. 시연 제어 패널의 초기화·시계·알림 실행·확인 방식·가위바위보 켜기/끄기를 잠근다 |
| `APPROVAL_API_PUBLIC` | 꺼짐 | 켜면 REST API를 밖에서도 연결 토큰으로 부를 수 있다(Claude Desktop stdio를 배포 서버에 붙일 때만) |
| `APPROVAL_CLOCK_FLOW` | 흐름(Docker는 `frozen`) | `frozen`이면 시연 시계가 멈춘다. 패널의 '시계 맞추기·앞으로'는 그대로 된다 |

## 3. AI 서비스별로 MCP 붙이는 법

| 서비스 | 붙일 수 있는 조건 [사실] | 이 서버에 붙이는 법 |
|---|---|---|
| ChatGPT 데스크톱 앱 (Windows·macOS) | 데스크톱 앱·Codex CLI·IDE 확장이 MCP 설정을 함께 쓴다. 설정 › MCP servers › Add server, STDIO 또는 Streamable HTTP. 헤더 인증(`bearer_token_env_var`, `http_headers`) 지원 (S6). 요금제 표에 Plus·Pro·Business·Enterprise/Edu (S7) | 주소 `…/mcp/<비밀값>/<slug>` 또는 주소 `…/mcp` + 헤더 토큰 |
| ChatGPT 웹 | 사용자 정의 MCP는 Business·Enterprise/Edu. Pro는 읽기만 (S1). Business는 관리자만 앱을 만들고 게시 (S1, S2). 공개 HTTPS 또는 Secure MCP Tunnel (S1, S8). 인증은 OAuth 또는 인증 없음, 사용자 정의 API 키는 안 됨 (S3, S4) | 관리자가 '인증 없음'으로 `…/mcp/<비밀값>/<slug>`를 게시. 사람마다 다른 사용자로 붙이려면 OAuth가 필요(4.3) |
| Claude (웹·데스크톱 사용자 정의 커넥터) | Anthropic IP 대역에서 공개 인터넷으로 닿아야 함 (S14). 인증 없음·OAuth. 고정 헤더는 베타·일부 조직 (S11) | `…/mcp/<비밀값>/<slug>`를 '인증 없음'으로 |
| Claude Desktop 로컬 (stdio) | `claude_desktop_config.json`의 로컬 서버는 PC에서 실행 (S14) | 배포 서버의 REST를 열어야 함(`APPROVAL_API_PUBLIC=1`). 배포에서는 권하지 않음 |

[해석]
- 데스크톱 앱은 사용자 PC에서 MCP 서버로 연결하는 것으로 보인다(10/20 실기에서 `127.0.0.1` 주소가 붙었다). 그렇다면 데스크톱 앱 참가자에게는 **사내망 서버**로도 충분하다. 문서로는 확인하지 못했다.
- 주소 안 비밀값은 접속 기록·브라우저 기록에 남는다. Claude 문서도 URL에 토큰을 넣지 말라고 한다 (S11). 헤더를 넣을 수 있는 데스크톱 앱에는 **헤더 토큰 방식**을 권한다.
- 대화마다 연결은 하나만 켠다(같은 대화에 기안자·결재자 연결이 함께 켜져 있으면 AI가 엉뚱한 연결을 고를 수 있다). 지금 시연 방식과 같다.

## 4. 사용자 구분 — 정한 것: "화면에서 고른 사용자 = 신원"

### 4.1 지금 동작
- **웹**: 오른쪽 위에서 사용자를 고른다(쿠키 `demo_user`). 로그인은 없다. 입장 코드는 "이 서버를 쓸 수 있는 사람"만 가른다.
- **MCP**: 연결(주소 또는 헤더 토큰)마다 사용자가 고정된다. 연결 2개 = 김지훈(기안자용) + 박서연(결재자용). [변경 10/26] 이전: 연결 8개(사례별 추가 6개 포함).
- 헤더 토큰은 `amk-<slug>-<20자>` 꼴이고 주소 비밀값에서 만든다. 문서에 공개된 시드의 REST 토큰으로는 `/mcp`가 열리지 않는다.

### 4.2 여러 사람이 같은 사용자를 고르면
같은 사람으로 일하므로 같은 초안·결재함을 함께 본다(예: 참가자 20명이 모두 김지훈 선임이면 서로의 초안이 섞인다).
[해석] 연수에서 조별로 쓴다면 **조마다 서버(또는 DB)를 따로** 띄우는 것이 가장 단순하다. 컨테이너 하나가 한 조다
(`APPROVAL_MCP_SECRET`, `APPROVAL_SITE_KEY`를 조마다 다르게).

### 4.3 (만들지 않음) OAuth 사용자 고르기
ChatGPT 웹(Business 이상)에서 **사람마다 다른 사용자**로 붙여야 할 때만 필요하다. 인증 없음 방식에서는 연결 하나가 사용자 하나라서,
관리자가 연결을 사용자 수만큼 게시해야 한다.
- 흐름: AI 서비스가 연결할 때 이 서버의 동의 화면이 뜨고, 거기서 사용자(사번)를 고르면 그 사용자로 토큰을 준다. 로그인 대신 "고르기"다.
- 필요한 것 [사실]: 보호 자원 메타데이터(`/.well-known/oauth-protected-resource`), 인가 서버 메타데이터, CIMD(권장) 또는 DCR,
  PKCE S256, `resource` 값으로 토큰 대상(aud) 확인 (S4, S10). ChatGPT 되돌아갈 주소 `https://chatgpt.com/connector_platform_oauth_redirect` (S4, S5),
  Claude `https://claude.ai/api/mcp/auth_callback` (S11).
- [해석] 작업량 1~2일 + ChatGPT Business 워크스페이스에서 실기 확인이 꼭 필요하다(여기서는 시험할 수 없다).

## 7. 검토 후 보류한 것 (10/23)

- **사이트 안 챗봇**: 툴 16개와 서버 지침을 그대로 써서 만들 수는 있다(함수 호출 + 이미지 입력). 별도 LLM API 키·사용료와
  ChatGPT·챗봇 두 경로 운영이 필요해 보류. 구성과 엔진 비교는 검토 문서에 남겼다.
- **ChatGPT 계정으로 직접 연결 (Sign in with ChatGPT)** [사실]: 다른 앱에서 ChatGPT 계정으로 로그인하고 그 사람의 요금제 사용량으로 모델을 부르는 기능이다 (S29).
  웹사이트 로그인은 선택된 상용 파트너의 제한 시범이고(대기 목록은 OpenAI 담당자) (S30), 요금제 사용은 Plus·Pro만 문서에 있다 (S29).
  [해석] 회사 계정(Business·Enterprise)을 쓰고 이 사이트가 파트너가 아니므로 당장은 쓸 수 없다.
- **OAuth 사용자 고르기**: ChatGPT 웹(Business 이상)에서 사람마다 다른 사용자로 붙여야 할 때만 만든다(4.3).
